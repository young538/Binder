## 3. 남아 있는 동작과 한계

- 브라우저 종료 중 네트워크 완료는 보장하지 않습니다. 초안은 sessionStorage에 저장되므로 같은 탭 재조회 때 복구하며 탭 종료 후 복구까지 보장하지 않습니다.
- 동일 필드를 여러 탭/기기에서 편집하면 마지막 서버 쓰기가 반영됩니다. 자동 저장 큐는 같은 브라우저 실행 컨텍스트 안에서 공유합니다.
- 연간 마이그레이션은 기존 표시 실적을 기준선으로 보존합니다. 이미 과거에 어긋난 수치의 원래 정답을 복원하지는 않습니다.
- 첫 주 시작일 설정은 저장되지만 주요 달력은 월요일 고정입니다.
- 목표 진행은 직접 연결 기준이며 보드 자손을 재귀 합산하지 않습니다. 주간 목표 요약의 월 지표는 그 주 월요일이 속한 월입니다.
- 시간 블록이 겹치면 각각의 길이를 더합니다.
- 주/월 횟수형은 표시 기간의 날짜 수에 비례해 기대치를 계산하고 습관별로 반올림합니다. 짧은 기간의 작은 월 목표는 기대치가 0일 수 있습니다.
- StoreProvider 초기 조회 실패는 재시도 버튼으로 복구합니다. 공통 비동기 리소스는 오류와 마지막 값을 제공하지만 모든 화면에 상세 오류 UI가 구현된 것은 아닙니다.
- 가져오기 성공 후 현재 페이지의 공통 store와 구독 리소스는 갱신합니다. 도메인 데이터의 다중 탭·기기 실시간 갱신은 없습니다.

## 4. 서버 검증 범위

HTTP 변경 경계는 `lib/server/validation.ts`, 순수 필드 규칙은 `lib/validation/mutations.ts`, 백업 검증은 `lib/server/importValidation.ts`에 있습니다. 백업은 BackupService가 검증과 저장을 한 즉시 트랜잭션으로 묶습니다. 내부 repository 호출이나 직접 DB 쓰기를 모두 검증하는 계층은 아닙니다. DB 외래키와 모든 논리 키의 UNIQUE 제약은 별도 보강 대상입니다. 습관 토글, 회고·한 문장 upsert, 연간 기본 7행 확보는 조회와 쓰기를 즉시 트랜잭션으로 묶습니다. 외부 직접 DB 쓰기까지 논리 키의 유일성을 강제하는 제약은 없습니다.

습관 체크 가능한 요일은 UI에서 제한합니다. API는 일정 형식·날짜·소유권을 검증하지만 일정 밖 날짜의 체크를 직접 금지하지 않습니다. 습관 달성률 집계에서는 해당 로그를 제외합니다. 로그인 시도 제한·MFA·세션별 강제 로그아웃은 이번 범위에 포함하지 않았습니다.

## 5. 삭제와 가져오기

연간 목표 삭제는 습관 연결도 해제하고 습관 삭제는 해당 로그를 지웁니다. 다른 일반 삭제의 참조 전체 정리와 보드 자손 삭제의 단일 트랜잭션화는 별도입니다.

Import는 본인 userId로 stamp하며 전체 검증 후 트랜잭션으로 처리합니다. 다른 사용자와 ID가 충돌하거나 참조 대상이 없으면 거절합니다. 기존에 삭제된 항목의 연결이 남은 백업은 연결을 정리해야 가져올 수 있습니다. ID 재발급·연결 ID 변환·버전별 변환은 제공하지 않으며 merge counts는 입력 행 수입니다. 새 연간 목표 백업은 수동 보정값까지 보존합니다.

## 8. 실제 서버 반영 확인 (2026-09-09)

사용자 화면에 중복 습관이 남아 있던 원인은 9월 6일 Docker 빌드가 계속 실행 중이었기 때문입니다. 당시 배포 번들에서 `주간 습관 달력`과 `오늘의 습관`을 확인했습니다.

SQLite 온라인 백업(`data/binder-before-weekly-unify-2026-09-09T06-00-09-152Z.sqlite`)과 이전 이미지 태그를 보존한 뒤 `docker compose build app`, `docker compose up -d --no-deps app`으로 검증한 최신 소스를 반영했습니다. 로그인 HTTP 200, 인증/DB 초기화 응답 401, DB integrity_check=ok와 연간 실적 마이그레이션 적용을 확인했습니다. 배포 번들에는 통합 `주간 습관 체크`가 있고 이전 중복 영역 문구는 없습니다.

## 9. 주간 배치와 통계 표시 보완 (2026-09-09)

상단 독립 습관 카드를 제거하고 시간표 아래 `WeeklyReview`로 옮겼습니다. 목표 진행 요약의 접힘을 해제하고 목표별·카테고리별 실제 시간 통계를 PC/모바일 모두 항상 표시합니다. 모바일의 불필요한 빈 높이를 줄이고 하단 고정 버튼 공간을 확보했습니다.

`weekly-efficiency`, `weekly-habits`, `week-input` E2E 11개와 Docker 프로덕션 빌드/타입 검사가 통과했습니다. PC·모바일 화면 이미지를 직접 확인한 뒤 실제 app 컨테이너에 반영하고 로그인 HTTP 200과 새 통계 영역이 포함된 배포 번들을 확인했습니다. 데이터 스키마 변경은 없습니다.

## 10. 하단 여백·시각 통합 (2026-09-09)

습관·통계를 시간표와 동일한 폭의 연속 영역으로 바꾸고 외곽 그림자·중복 테두리·중첩 패딩을 제거했습니다. 모바일 자체 하단 여백은 160px에서 76px+safe-area로 줄이고 공통 메뉴의 64px 여백을 활용합니다. PC는 12px을 사용합니다. 통계는 계속 펼쳐 표시하며 데이터 계산에는 변경이 없습니다.
