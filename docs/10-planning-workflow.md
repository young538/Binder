# 계획·실행·회고 연결 기능

[문서 목차](README.md) · [데이터 모델](02-data-model.md) · [API](03-api.md) · [검증 기록](05-verification-and-limitations.md)

2026-11-06 추가한 기능의 사용법과 저장 규칙입니다. 운영 배포 여부는 검증 기록에서 별도로 확인합니다.

## 기능과 진입점

| 기능 | 어디에서 사용하는가 | 결과 |
|---|---|---|
| 회고 → 할 일 | 일일 기록·일일 회고 시트·주간 회고의 **할 일로 추가** | 다음 날/다음 주 할 일과 원래 회고 연결 |
| 계획 대비 실제 시간 | 주간 화면의 통계·주간 회고 | 카테고리별 계획/실제 시간과 차이 |
| 반복 할 일 | 일일·주간 날짜 열·월간 날짜 서랍·수집함 항목의 **상세 설정** | 완료 시 다음 날짜의 할 일 생성 |
| 주간 계획 템플릿 | 주간 화면 위 **주간 계획 템플릿** | 계획 시간표 저장·미리보기·다른 주 적용·삭제 |
| 책별 독서 기록 | 독서 리스트의 **독서 기록 보기** | 누적 쪽수·독서한 날·날짜별 노트 |
| 목표 실행 점검 | One-Thing 보드의 **목표 실행 점검**, 모바일 더보기 | 하위 목표를 포함한 최근 14일 실행 현황 |
| 빠른 메모·수집함 | 모든 로그인 화면의 **빠른 메모**, Alt+N, 상단 수집함/모바일 더보기 | 날짜 없는 할 일을 모으고 나중에 날짜·목표 배정 |

## 1. 회고를 다음 행동으로 옮기기

1. 회고의 **내일/다음주 1가지**를 작성합니다. 공백뿐이면 추가 버튼은 비활성입니다.
2. **할 일로 추가**를 누릅니다. 일일 회고는 보고 있는 날짜의 다음 날, 주간 회고는 다음 ISO 주차가 기본입니다. 현재 실제 날짜 기준이 아닙니다.
3. 실행 날짜 또는 주차와 할 일 제목을 확인·수정하고 **할 일 등록**을 누릅니다.
4. 회고 저장을 먼저 완료한 뒤 할 일을 생성합니다. 저장 실패 시 입력을 유지하며 재시도합니다.
5. 완료 메시지의 **등록한 목록 보기**로 이동합니다. 할 일의 상세 설정에는 **원래 회고 보기** 링크가 있습니다.

일일은 `scope=day`, 주간은 `scope=week`로 생성합니다. 원문은 삭제하거나 자동 변경하지 않습니다. 이후 회고를 수정해도 이미 만든 할 일 제목은 바뀌지 않습니다.

같은 사용자·원본 회고·제목·대상 기간의 할 일이 남아 있으면 해당 항목을 재사용합니다. 새로고침·다른 탭에서도 중복 생성을 막습니다. 일반 입력으로 만든 같은 제목의 할 일이나 다른 회고에서 만든 할 일은 별개입니다. 삭제 후 새 등록 동작은 다시 생성할 수 있지만, 응답 유실에 대한 동일 요청 키 재전송은 기존 응답을 유지합니다.

## 2. 계획 대비 실제 시간

기존 시간블록의 `plan`과 `actual`을 카테고리별로 각각 합산합니다. 차이는 **실제 − 계획**입니다. 예를 들어 계획 2.0h, 실제 1.0h이면 차이는 -1.0h입니다. 한쪽 기록만 있는 카테고리도 표시합니다.

위 막대는 계획, 아래 막대는 실제입니다. 모든 카테고리에 공통 축을 사용합니다. 겹치는 블록도 각각 합산하며, 시간의 일치나 차이를 할 일 완료율로 해석하지 않습니다. TODO 상태는 별도입니다. 이 비교는 주간 회고와 주간 화면에서 같은 컴포넌트를 재사용합니다.

## 3. 반복 할 일

항목의 상세 설정에서 날짜를 지정하고 **반복 할 일**을 켭니다. 간격은 1~365, 단위는 일·주·개월입니다.

| 반복 기준 | 다음 날짜 |
|---|---|
| 예정일 기준 | 해당 항목의 실행 날짜 + 반복 간격 |
| 완료일 기준 | 서버가 기록한 서울 날짜 + 반복 간격 |

완료 상태로 바뀔 때 다음 할 일을 한 번 생성합니다. 다음 항목은 미완료 상태이며 제목·메모·카테고리·목표·반복 규칙을 이어받습니다. 다음 날짜 목록의 끝에 배치하고 기존 시간블록은 복사하지 않습니다. 생성과 완료 기록을 한 즉시 트랜잭션으로 처리하므로 중간 실패 시 둘 다 롤백합니다.

- 완료 재전송, 완료 취소 후 재완료로 다음 항목이 늘어나지 않습니다.
- 완료를 취소해도 이미 생성된 다음 항목은 유지합니다. 이후 반복 변경·중지는 다음 항목에서 설정하세요.
- 예정일 기준으로 늦게 완료하면 다음 날짜도 과거일 수 있습니다. 누락된 기간을 건너뛰거나 한꺼번에 생성하지 않습니다.
- 월 반복은 해당 날짜가 없으면 월말로 맞춥니다. 다음 반복은 조정된 날짜를 기준으로 계산합니다. 예: 1/31 → 2/28 → 3/28.
- 날짜를 비워 수집함으로 옮기면 반복도 해제합니다. 주·월·연 단위 TODO에는 반복을 설정하지 않습니다.
- 삭제된 카테고리·목표 연결은 다음 항목 생성 시 해제합니다.

## 4. 주간 계획 템플릿

현재 보고 있는 주에 계획 시간블록을 만든 뒤 템플릿 이름을 입력하고 **이 주를 템플릿으로 저장**을 누릅니다. 템플릿에는 요일 위치·시작/종료 시간·내용·카테고리·목표를 저장합니다. 실제 기록과 TODO 연결은 제외합니다. 계획 1~500개인 주를 저장할 수 있습니다.

저장한 템플릿을 선택하면 요일·시간·내용을 미리 볼 수 있습니다. 적용할 주를 선택하고 **이 주에 적용**을 누르면 기존 시간표에 계획이 추가됩니다. 기존 기록을 지우지 않으며 겹침을 자동 조정하지 않습니다.

동일 템플릿·대상 주·항목 위치로 만든 시간블록은 안정적인 ID를 사용합니다. 재적용은 남아 있는 항목을 건너뛰고 수정 내용도 보존합니다. 적용한 항목을 삭제한 뒤 재적용하면 삭제한 항목은 다시 생성합니다. 다른 템플릿의 동일 시간·내용은 별도 계획입니다.

템플릿은 저장 당시의 스냅샷입니다. 원본 주를 수정해도 자동 변경되지 않으므로 새 이름으로 다시 저장하고 이전 템플릿을 삭제할 수 있습니다. 템플릿 삭제는 이미 적용한 시간표에 영향을 주지 않습니다. 카테고리가 삭제되면 전체 적용을 거절하며 원본 주 수정·재저장을 안내합니다. 삭제된 목표는 연결을 해제하고 적용합니다.

## 5. 책별 독서 기록

독서 리스트의 책 아래 **독서 기록 보기**를 누르면 연결된 모든 연도의 일일 기록을 날짜순으로 보여줍니다. 일일 독서의 책 선택지도 모든 연도를 포함하고 책 목록 변경을 재조회합니다.

- 연결은 `bookId` 기준입니다. 제목이 같아도 다른 책 ID이면 합치지 않습니다.
- 누적 쪽수는 날짜별 입력 쪽수의 합입니다. 다시 읽은 쪽수도 포함합니다.
- 독서한 날은 연결된 기록의 고유 날짜 수입니다. 쪽수 0인 독서 노트도 포함합니다.
- 날짜를 누르면 해당 일일 기록으로 이동해 수정할 수 있습니다. 다음 상세 조회에 반영됩니다.
- 제목 직접 입력 기록은 책 ID가 없으므로 자동 연결하지 않습니다.
- 완독일·연간 목표·독서 습관은 자동 변경하지 않습니다. 삭제된 책의 기존 일일 노트는 보존합니다.

## 6. 목표 실행 점검

`/goal-review`에서 기준 날짜를 선택합니다. 기준일을 포함한 최근 14일 동안 각 목표와 모든 하위 목표의 완료 할 일 수·습관 체크 수·실제 기록 시간을 보여줍니다. 미완료·연기 할 일은 기간과 무관하게 목록을 펼쳐 확인하고 해당 화면으로 이동할 수 있습니다.

완료·체크·실제 시간이 모두 없으면 **14일간 실행 기록 없음**으로 표시합니다. 계획 시간만 입력하거나 목표 제목을 수정한 것은 실행으로 세지 않습니다. 습관 체크는 같은 습관·날짜 중복을 제거합니다. 상위 목표의 수치는 하위 목표를 포함하므로 화면의 모든 카드 수치를 다시 합치면 중복됩니다. 기존 목표 진행률의 직접 연결 계산은 그대로 유지합니다.

새 TODO 완료는 서울 날짜로 집계합니다. 완료 시각이 없는 과거 day TODO는 실행 날짜를 대체 기준으로 사용하며, 과거 week/month/year TODO의 완료 시각은 추정하지 않습니다. 삭제·상태 변경 뒤 재조회하면 현재 데이터 기준으로 다시 계산합니다.

## 7. 빠른 메모와 수집함

**빠른 메모** 또는 Alt+N으로 제목만 입력해 수집함에 저장합니다. 일반 TODO 입력과 같은 한글 조합·중복 제출·실패 재시도 처리를 사용합니다. 수집함은 `scope=inbox`, `scopeKey=inbox`인 TODO 목록입니다.

상세 설정에서 메모·목표·실행 날짜를 지정합니다. 날짜를 정하면 같은 ID의 일일 TODO로 이동하며 수집함에서는 사라집니다. 날짜를 비우면 수집함으로 돌아갑니다. 수집함의 항목도 상태 변경·삭제 취소·전체 검색·백업을 지원합니다.

## 저장·백업·유지보수

[0007 마이그레이션](../drizzle/0007_short_shatterstar.sql)은 `weekly_templates` 테이블과 `todos`의 `repeat_rule`, `source_retro`, `completed_at`, `repeat_generated` 열만 추가합니다. 기존 행·ID를 재작성하지 않습니다. 마이그레이션은 최초 DB 접근 때 적용됩니다.

JSON 백업은 version 11이며 11개 컬렉션을 포함합니다. 새 TODO 필드와 주간 템플릿도 내보내고 복원합니다. 새 필드·컬렉션이 없는 이전 백업은 계속 가져올 수 있습니다. 템플릿 내부 카테고리·목표 참조도 사용자 소유권과 함께 검증합니다. `repeatGenerated`를 복원해 완료 취소·재완료로 반복 항목이 다시 생성되는 것을 막습니다. `completedAt`과 `repeatGenerated`는 일반 API 입력으로 수정할 수 없습니다.

운영 반영 전 SQLite 온라인 백업과 기존 이미지를 보존하세요. 이전 앱은 새 수집함·반복 규칙·템플릿을 해석하지 못하므로 기능을 사용한 DB에 이전 앱만 연결하는 것은 완전한 기능 롤백이 아닙니다. 복구 시점 이후의 데이터 손실 여부를 확인하고 [운영 복구 절차](04-development-and-operations.md)를 따릅니다.
