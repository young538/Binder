# 일일 트래커와 루틴 관리

[전체 목차](../README.md) · [연간 목표](03-annual.md) · [회고](07-retrospective.md)

## 목적과 URL

`/daily`는 오늘로 이동하고 `/daily/YYYY-MM-DD`는 특정 날짜의 실행 기록을 보여줍니다. 날짜 파라미터는 형식과 실제 연·월·일을 검사합니다. `2026-02-30`처럼 존재하지 않는 날짜는 `/daily`로 되돌립니다.

이전 날·다음 날 이동과 오늘로 돌아가기가 있습니다. 날짜 헤더 아래 하루 계획과 실제 기록을 보여줍니다. PC는 왼쪽 루틴, 오른쪽 오늘 할 일·오늘의 독서를 배치하며 오른쪽 열은 전체 폭의 약 41%를 사용합니다. 오늘의 독서는 기본으로 펼쳐지며 헤더를 눌러 접을 수 있습니다. 하루 기록은 하단 전체 폭을 사용하고, 좋았던 것·아쉬운 것·다음 행동은 PC에서 나란히, 자유 메모는 그 아래에 표시합니다. 작은 화면은 모든 영역을 세로로 배치합니다.

## 하루 계획과 실제

선택 날짜의 `time_blocks`를 읽어 계획(`plan`)과 실제 진행(`actual`)으로 나눕니다. 일일과 주간은 동일한 `TimeGrid`를 사용하며 일일은 선택 날짜 하나, 주간은 7개 날짜를 전달합니다. 시간 눈금·행 높이(32px)·카테고리 색상·계획 점선/실제 실선과 선택 표시가 같습니다. 설정한 시작·종료 시간과 격자 간격도 동일하게 적용합니다. 일일 시간표는 최대 높이 520px 안에서 스크롤합니다.

한 번 클릭하면 칸이나 기록을 선택합니다. 마우스 더블클릭·Enter·F2 또는 선택 바의 편집 버튼으로 편집기를 엽니다. 마우스로 빈 시간 범위를 드래그하면 시작·종료 시간이 자동 입력됩니다. 기록 드래그는 이동, Alt/Ctrl/Command+드래그는 복사이며 계획·실제 열 사이에서도 동작합니다. 편집기의 다음 날 복사도 주간과 같습니다. Escape는 진행 중인 드래그를 취소합니다.

터치 화면에서는 빈 칸과 기록 위 어디서든 쓸어 넘겨 스크롤합니다. 터치 드래그로 범위를 생성하거나 기록을 이동하지 않으며, 두 번 탭해도 편집기를 열지 않습니다. 한 번 탭해 선택한 뒤 선택 바의 `편집` 또는 `새로 만들기` 버튼으로 편집기를 엽니다. 이 규칙은 일일·주간의 공통 시간표에 적용됩니다.

`목록` 전환은 기존 일일 목록을 제공합니다. 목록에서는 항목을 한 번 눌러 바로 편집하며 시간 구간·소요 시간·내용·연결 카테고리/목표를 확인할 수 있습니다. 목록은 PC 두 열, 모바일 세로 배치입니다. 상단 합계 시간은 겹치는 시간도 각 기록 길이로 합산합니다.

목록의 `계획 추가`와 `실제 기록 추가`는 해당 종류를 선택한 편집기를 엽니다. 목록의 기존 항목을 누르면 내용·시간·종류·카테고리·목표·해당 날짜 할 일을 편집하거나 삭제할 수 있습니다. 종료 시각 00:00은 해당 날짜의 자정(1440분)입니다. 계획을 실제로 바꾸면 같은 항목의 종류가 바뀌며 자동 복제하지 않습니다.

주간 화면과 같은 DB 행과 `BlockEditor`를 사용하므로 주간에서 만든 항목도 표시되고 편집한 결과가 이어집니다. 변경 이벤트는 선택 날짜를 재조회하고 오래된 응답을 무시합니다. 날짜 이동 시 편집기와 목록 상태는 초기화합니다. 조회 실패는 재시도, 저장 실패는 입력을 보존한 오류 메시지를 제공합니다. 카테고리가 없으면 설정에서 만든 뒤 추가할 수 있습니다.

## 고정 루틴

습관 전체와 선택 월·선택 주를 모두 포함하는 범위의 습관 로그를 병렬 로딩합니다. 매일 습관과 선택 날짜의 요일에 해당하는 습관만 고정 루틴에 포함합니다. 주 N회·월 N회는 별도 영역입니다.

카테고리가 있는 루틴은 카테고리별로 묶고 카테고리 순서대로 보여줍니다. 카테고리가 없거나 찾을 수 없으면 기본 고정 루틴 그룹에 표시합니다. 완료 행에는 체크·배경색·취소선을 표시하고 루틴 메모가 있으면 반복 일정 대신 설명으로 보여줍니다.

완료율 = 선택 날짜에 체크한 고정 루틴 수 / 그 날짜의 고정 루틴 수 × 100입니다. 루틴이 없으면 0%이고 횟수형은 분모에 포함하지 않습니다.

체크 중인 습관은 버튼을 비활성화해 반복 클릭을 막습니다. 서버 토글 응답을 받은 뒤 현재 날짜가 같은지 확인하고 화면 로그를 갱신합니다. 이후 변경 알림을 약 250ms 모아 목록을 재조회합니다. 로딩 실패·체크 실패 메시지와 재조회 버튼도 있습니다.

## 빈 상태의 기본 루틴

습관이 하나도 없을 때 기본 프리셋 또는 직접 만들기를 제공합니다. 프리셋 이름은 현재 “9월 트래커 루틴 추가”입니다.

기본 항목은 오늘 일정 정리, 명상/묵상, 독서, 감사한 일 기록, 스쿼트 + 팔굽혀펴기, 복근 운동, 차승헌 운동의 7개입니다. 모두 매일 일정이며 목표·카테고리 연결 없이 생성합니다. 명칭은 9월이지만 실제 데이터는 9월에 한정되지 않습니다.

프리셋은 7개 API 요청으로 생성하므로 중간 실패 시 일부만 남을 수 있습니다. 일부가 생성되어 습관 수가 0보다 커지면 같은 프리셋 버튼 대신 관리 화면으로 보완해야 합니다.

## 주 N회·월 N회 루틴

횟수형은 어느 날짜에나 체크할 수 있고 해당 기간 완료 수와 목표 횟수를 표시합니다. 주간 범위는 월~일, 월간 범위는 월초~말입니다. 표시 퍼센트는 최대 100%입니다.

선택 월과 주를 모두 읽으므로 월 경계 주의 인접 월 체크도 진행 수에 포함합니다. 같은 습관을 하루 여러 번 체크하는 횟수 입력은 없으며 하루 완료 여부를 토글합니다.

## 루틴 관리 시트

페이지의 루틴 관리 버튼이 `DailyRoutineSheet` 안에 `HabitEditor`를 엽니다. 현재 습관 편집의 실제 진입점입니다.

| 항목 | 구현 |
|---|---|
| 이름·색·메모 | 습관 레코드 편집 |
| 반복 | 매일 / 요일 / 주 N회 / 월 N회 |
| 요일 | 일=0~토=6, UI에서는 최소 하루 유지 |
| 횟수 | UI에서 1~99로 제한 |
| 카테고리 | 선택·해제, 일일 화면 그룹에 반영 |
| 상위 목표 | 보드 목표와 연결 |
| 연간 목표 | 현재 연도 목록에서 연결; 서버가 목표 수치 계산 |
| 순서 | 손잡이를 드래그, `order=0..n-1`로 저장 |
| 삭제 | 확인 후 습관과 해당 습관 로그 삭제 |

드래그는 `motion/react`의 Reorder와 drag controls를 사용합니다. 마지막 정렬 후 350ms에 변경된 order만 PATCH하고, 시트가 닫힐 때 보류 중인 순서도 저장을 시도합니다. 다른 필드는 이벤트마다 저장합니다.

## 오늘의 TODO

`TodoListSection(scope=day, scopeKey=date)`를 사용합니다. 새 입력은 공통 TodoCreateInput이 처리하며 Enter·포커스 이탈이 겹쳐도 한 번만 저장하고 한글 조합 Enter는 무시합니다. 추가, 명시적 제목 편집, 상태 선택, 카테고리 지정·해제, 삭제를 제공합니다. 월간 날짜 서랍·주간 날짜 열과 같은 TODO입니다. 고정 루틴 체크와 TODO 완료는 서로 독립적입니다.

## 메모 데이터

일일 화면에는 별도 `DailyMemo` 입력 UI를 표시하지 않습니다. 일일 메모 데이터(`focus_notes(scope=day, scopeKey=YYYY-MM-DD)`)는 기존 값과 저장 구조를 그대로 보존하며, 마이그레이션하거나 삭제하지 않습니다. 기존 `DailyMemo` 데이터는 일일 회고의 자유 메모와 별도 데이터입니다.

현재 메모 입력은 `DailyRecord`의 자유 메모를 사용합니다. 자유 메모와 기존 `focus_notes` 데이터는 서로 합치거나 자동으로 복사하지 않습니다.

## 오늘의 독서

책 목록은 **모든 연도**를 조회하고 목록 변경 때 재조회합니다. 독서 리스트의 **독서 기록 보기**에서 같은 책 ID의 누적 쪽수와 날짜별 노트를 확인할 수 있습니다. [책별 독서 기록 안내](../10-planning-workflow.md#5-책별-독서-기록)를 참고하세요.

`DailyReading`은 큰 제목으로 표시되고 기본으로 펼쳐져 책 선택 또는 제목 직접 입력, 읽은 쪽수, 독서 노트를 바로 기록할 수 있습니다. 헤더를 누르면 접힙니다. 접힌 헤더의 책·쪽수 요약은 긴 제목도 줄바꿈해 전체 내용을 읽을 수 있습니다. 기본 쪽수는 10, 빠른 선택은 10·20·30, 입력 범위는 0~9999입니다. `독서 노트` 입력란은 16px 글꼴, 32px 줄 높이, 최소 높이 320px로 표시되며 긴 글에 맞춰 자동으로 늘어납니다.

날짜당 하나의 `ReadingEntry`를 JSON 문자열로 저장합니다.

```json
{
  "bookId": "선택한-책-ID",
  "bookTitle": "책 제목",
  "pages": 10,
  "memo": "읽은 내용 한 줄"
}
```

저장 위치는 `retrospectives(type=daily, dateOrWeek=date).template.reading`입니다. 기존 reading이 JSON이 아니면 메모 문자열로 취급합니다. 책을 직접 입력해도 연간 책 목록에 자동 추가하지 않으며, 완독일·연간 실적·독서 습관 체크도 자동 변경하지 않습니다.

독서와 회고는 수정한 template 필드만 전송합니다. 서버가 트랜잭션 안에서 기존 필드와 합치므로 독서를 저장해도 같은 날의 good·bad·nextStep을 보존합니다.

## 일일 기록과 저장 완료

**내일/다음주 1가지**의 **할 일로 추가**는 보고 있는 날짜의 다음 날을 기본으로 제안합니다. 회고 저장 후 할 일을 만들며 원본 회고 연결을 보존합니다. 오늘의 TODO 상세 설정에서는 날짜·목표·메모·반복 규칙을 편집합니다. [연결 기능 안내](../10-planning-workflow.md)를 확인하세요.

`DailyRecord`가 `RetroTemplate`을 일일 화면에 인라인으로 표시합니다. 점수, 좋았던 것, 아쉬운 것, 다음 행동, 자유 메모를 작성합니다. 파란색 헤더와 질문별 제목으로 구분하고 본문은 16px 글자·32px 줄 간격을 사용합니다. 질문 입력은 최소 176px, 자유 메모는 최소 224px이며 내용과 화면 폭에 맞춰 높이가 늘어납니다. 독서 노트와 같은 `GrowingTextarea`를 재사용합니다. 주간 화면의 일일 회고 버튼은 별도로 기존 세로 배치의 `DailyRetroSheet`를 엽니다.

자동 저장은 마지막 입력 후 약 1초에 실행하며, 화면 이동·시트 닫기 때 보류된 입력을 즉시 저장 요청합니다. 사용자·기록별 큐가 요청을 순서대로 처리하고 실패한 입력을 보존합니다. 저장 상태와 재시도를 표시하고 sessionStorage에 탭별 초안을 보관합니다. 브라우저 강제 종료 때 네트워크 완료는 보장하지 않으며, 탭을 닫으면 sessionStorage 초안도 사라질 수 있습니다.

## TODO 이월과 삭제 취소

날짜별 TODO 목록의 **미완료 N개 다음 날로**를 누르면 pending·postponed 항목이 다음 날짜로 이동합니다. 같은 ID를 유지하며 시간 기록은 원래 날짜에 남습니다. 월/주 단위 TODO에는 이월 버튼을 표시하지 않습니다. 삭제 후 하단 알림의 **실행 취소**로 30초 이내 같은 TODO를 복원할 수 있습니다. 알림은 현재 브라우저에서만 표시되고 새로고침 뒤에는 유지되지 않습니다.
