# One-Thing 보드

## 목적과 화면 구성

URL은 `/mandalart`입니다. 인생 한 문장인 One-Thing 아래에 8개 핵심 목표, 각 핵심 목표 아래에 8개 세부 목표를 배치합니다. 보드에는 연도 필드가 없으며 계정별 하나의 목표 집합을 사용합니다.

화면은 9×9 격자와 자유노트입니다. `lg` 이상에서는 격자 왼쪽·노트 오른쪽, 더 작은 화면에서는 세로로 배치합니다. 모바일에서도 보드 자체는 9열입니다.

| 위치 | 데이터 |
|---|---|
| 전체 중심 `(4,4)` | `oneThing` 1개 |
| 중앙 3×3의 주변 8칸 | `mandalartCore` 8개 |
| 바깥 3×3 블록의 중심 | 코어 목표의 동일 데이터 재표시 |
| 바깥 블록의 주변 8칸 | 각 코어의 `mandalartSub` |

81개의 칸이 81개 목표를 뜻하지 않습니다. 코어를 두 번 표시하므로 전체를 채우면 고유 목표는 1 + 8 + 64 = 73개입니다.

## 목표 작성과 편집

보드 위 **목표 실행 점검**은 별도 `/goal-review`로 이동합니다. 선택 기준일의 최근 14일 동안 하위 목표까지 포함한 실행 현황과 기록이 없는 목표를 확인합니다. 기존 칸의 연결 개수·진행률 계산은 바뀌지 않습니다. [점검 화면 사용법](../10-planning-workflow.md#6-목표-실행-점검)을 확인하세요.

칸을 누르면 제목 편집 모달이 열립니다. 먼저 중앙 목표, 다음 코어, 마지막 서브 순서로 생성합니다. 상위 목표가 없는 하위 칸은 안내 메시지와 함께 생성을 막습니다.

기존 목표는 `PATCH /api/goals/[id]`, 빈 칸은 `POST /api/goals`로 저장합니다. 위치는 `level`, `parentId`, `order`로 결정하며 별도의 행·열 좌표를 저장하지 않습니다. 저장 후 공통 목표 목록을 다시 읽어 보드를 만듭니다.

저장 버튼 또는 Enter로 저장하고 Escape·취소·배경 클릭으로 닫습니다. 한글 조합 중 Enter는 저장으로 처리하지 않습니다. 빈 제목으로 저장하면 모달만 닫힙니다.

## 연결된 연간 계획

기존 목표의 모달에는 현재 연도의 `parentGoalId`가 일치하는 연간 목표가 표시됩니다. 제목, 단위, 목표 수치, 기한을 입력해 연간 목표를 추가할 수 있습니다.

양수 목표 수치가 있으면 **습관도 함께 만들기**를 선택할 수 있고 기본은 선택 상태입니다. 기본 반복은 연 목표를 12로 나눠 반올림한 월 횟수입니다. 결과가 1 미만이면 월 1회, 28 이상이면 매일로 바꿉니다. 습관에는 보드 목표 ID와 새 연간 목표 ID를 함께 연결합니다.

습관을 만들면 서버가 반복 일정으로 연간 목표 수치를 다시 계산합니다. 예를 들어 연 60회는 월 5회로 유지되지만 연 10회는 월 1회, 즉 연 12회로 달라질 수 있습니다. 모달에 입력한 숫자가 항상 최종 수치는 아닙니다.

칸의 연결 개수는 해당 목표에 직접 연결된 습관 수와 현재 연간 목표 수의 합입니다. TODO 수나 자손 목표 전체의 연결 수가 아닙니다. 모달의 연간 계획 목록 옆 반복 표시는 목표 수치로 계산한 추천 일정이며 실제 연결 습관을 조회한 일정 표시와는 다릅니다.

## 자유노트와 삭제

자유노트는 `focus_notes`의 `scope=board`, `scopeKey=main`으로 저장하며 마지막 입력에서 약 1초 후 자동 저장합니다.

목표 삭제 시 화면이 현재 목표 목록에서 하위 목표를 재귀 수집해 각 ID의 삭제 API를 호출합니다. 서버의 단일 목표 삭제 함수는 그 한 행만 삭제합니다. 연간 목표·습관·TODO·시간블록의 연결 ID를 자동 정리하지 않으며, 여러 삭제 요청이 하나의 트랜잭션으로 묶이지도 않습니다.

연결 개수와 모달의 연간 목록 조회는 `useAsyncResource`를 사용합니다. 모달 대상이 바뀌면 입력 세션을 분리하며 이전 대상의 늦은 조회 응답을 무시합니다.
